# Changelog

이 프로젝트의 모든 주요 변경 사항을 기록합니다.

## [0.1.7] - 2026-07-25

### Added
- **장음(~)/탁음(^) 수동 마커**: 한글 음절 바로 뒤에 `~`를 붙이면 장음이 강제로 추가되고(도쿄~ → どきょう), `^`를 붙이면 해당 음절이 탁음으로 전환됨(카^ → が). 통계 모델이 놓치기 쉬운 케이스를 사용자가 직접 보정할 수 있도록 함. 연구논문(4.7절, 표 8)에서 유사한 틸드 마커 실험이 정확도를 -22.3%p 낮췄던 것과 달리, 이번엔 마커가 붙은 음절만 국소적으로 정적 규칙(`decode_word_with_markers`)을 적용하고 나머지 문장은 기존 학습된 `PhoneticMap`/`KNOWN_WORDS`/`KNOWN_SUFFIXES` 경로를 그대로 타므로 전체 정확도에 영향이 없음. `crates/db/src/phonetic_decoder.rs`에 구현, `ime-db` 14개 테스트 전부 통과.
- 마커 기반 변환도 학습된 `PhoneticMap`을 우선 조회(`base_reading_for_marker`)하도록 하여, 같은 단어를 마커 없이 변환했을 때와 자음 기본값이 어긋나지 않게 함.
- macOS 앱에서 `~`/`^`가 조합 중 실제로 Rust 엔진까지 전달되도록 `HJInputController.swift`의 `handle()`에 라우팅 분기 추가 (이전에는 두 문자가 바로 커밋되어 엔진에 도달하지 못했음).
- 패키지 `README.txt`와 홈페이지 튜토리얼에 사용법 안내 추가.

## [0.1.6] - 2026-07-25

### Fixed
- **`vocab_large.rs` 조합 생성 어휘 제거**: 통계 분석 결과 확인 — 2글자 단어 18,400개(전체 확장 어휘의 81%)가 어간 한자 약 340개 × 어미 한자 약 20개의 완전한 카테시안 곱으로 생성됨 (예: 어미 食는 344개의 서로 다른 어간과 결합 — 실제 사전에는 있을 수 없는 패턴). 読学, 置学 등 실존하지 않는 단어가 후보창에 뜨던 원인. `hj_engine_init()`(macOS 앱)과 `crates/wasm`(홈페이지) 양쪽에서 완전히 제거.
- 부수 효과: PhoneticMap 토큰당 평균 모호성이 1.5 → 1.2로 감소 (노이즈 감소, 258→233 학습 토큰으로 커버리지는 소폭만 감소).
- 어휘 구성이 이제 `vocab.rs`(731) + `vocab_extended.rs`(711) + `vocab_gapfill.rs`(279) = **1,721개, 전부 검증된 실제 단어**로 단순화됨.

## [0.1.5] - 2026-07-25

### Fixed
- **조사 が 오변환 수정**: が(주격 조사)가 か로 잘못 변환되던 문제 (예: 이로가 → いろか, 色が/いろが가 맞음). ㄱ 초성의 무성음 우세 확률(k 60% vs g 30%) 때문에 발생 — 와→は 수정과 동일한 패턴. `KNOWN_SUFFIXES`에 ("가","が") 추가.

### Added
- **홈페이지 문장 연습에 한자 변환 추가** (`homepage/kanji-dict.js`, 1,140개 검증된 한자 매핑): `vocab.rs`+`vocab_extended.rs`+`vocab_gapfill.rs`(검증된 어휘 1,721개)만 사용 — `vocab_large.rs`는 제외.
- **`vocab_large.rs` 데이터 품질 문제 발견**: 22,741개 항목 중 기본 731개를 제외한 대부분이 한자를 기계적으로 조합해 만든 실존하지 않는 단어(読学·置学 등)로 확인됨. 연구논문 4.7절의 "어휘 확장이 오히려 정확도를 낮췄다"는 결과의 원인으로 추정. 홈페이지 한자 사전에서는 제외했으나, 실제 앱의 `hj_convert()` 후보창에는 여전히 포함되어 있어 향후 정리 필요 (`docs/MODEL.md` 참고).

### Changed
- 홈페이지에서 작은 "Try it yourself" 데모 박스 제거, 문장 연습("sentence mode") 하나만 유지.

## [0.1.4] - 2026-07-25

### Added
- **어휘 공백 대량 보강** (`crates/db/src/vocab_gapfill.rs`, 279개 신규 항목): 의문사(何/誰/どこ/いつ/なぜ/いくつ/いくら 등)가 통째로 빠져있던 것을 포함해, 숫자/조수사, 가족·관계 호칭, 색깔, 신체 부위, 감정/성격 표현, 형용사, 일반 동사, 인사말/관용구, 부사 등 폭넓은 카테고리를 手작업으로 감사(audit) 후 채움.
- 감사 방법: N5~N3 수준 상용 단어 약 150개를 표본으로 뽑아 기존 24,914개 어휘와 대조 → 49개 확실한 공백 확인 → 카테고리를 넓혀 최종 279개로 확장.
- `hj_engine_init()`이 이제 어휘 4종 세트(731+711+22,741+279 = **25,193개**)를 조합해서 씀.

### Fixed
- '나마에'(名前, 이름) 등 기초 단어가 후보창에서 한자로 안 뜨던 문제 — 사전에 아예 없어서였음. 이제 `名前`가 칸지 후보로 정상 조회됨 (단, 실시간 조합 텍스트 경로는 원래도 히라가나까지만 감 — `docs/MODEL.md` 6.1절 참고).

## [0.1.3] - 2026-07-22

### Fixed
- **조사 は 오변환 수정**: 문장에서 조사로 쓰인 '와'가 わ로 잘못 변환되던 문제 (예: 나마에와 → なまえわ, なまえは가 맞음). `BeamDecoder::decode_sentence()` 추가 — 문장을 공백 기준으로 단어 분리 후, 표준 조사/어미 규칙을 문자 단위 통계 모델보다 우선 적용. 실제 macOS 앱의 실시간 변환 경로(`hj_hangul_to_hiragana`)에도 동일하게 적용됨.
- **です/ます 활용형 탁음 오류 수정**: '데스', '데스카', '마스' 등으로 끝나는 단어가 ㄷ 초성의 무성음 우세 확률(t 60% vs d 40%) 때문에 てすか처럼 잘못 변환되던 문제 (난데스카 → なんてすか, なんですか가 맞음).
- **실제 앱 어휘 크기 확대**: `hj_engine_init()`이 731개 단어(`build_vocab()`)만 쓰던 것을, 24,914개 전체 어휘(`build_vocab()` + `build_extended_vocab()` + `build_vocab_large()`)를 쓰도록 변경. 참고: 저장소의 `data/hj-ime-large.db`(11만 문장 학습 산출물)는 실제 앱 초기화 경로에 연결된 적이 없었음 — 연구용 산출물로만 존재했음. 이번 수정은 그것과 무관하게, 앱이 기동 시 즉석에서 구축하는 어휘를 확장한 것.

## [0.1.2] - 2026-04-07

### Fixed
- **종성 ㄴ 변환 실패 수정**: 곤(こん), 산(さん), 칸(かん), 킨(きん) 등 받침 ㄴ이 있는 글자가 변환되지 않고 한글 그대로 출력되던 버그 수정. `romaji_to_hiragana_simple()`에서 `kon`, `san` 등이 `ends_with("on")`, `ends_with("an")` 조건에 걸려 ん 분리가 실패하던 문제. 종성을 romaji에 합치지 않고 별도로 처리하도록 구조 변경.
- **관용 표기 변환 지원**: '곤니찌와' → こんにちわ 정상 변환 (v0.1.0에서는 '곤にじわ' 출력)
- **ㅉ→ち 매핑 강화**: ㅉ(쌍지읒)의 초성 매핑에서 ch 확률을 0.35로 상향 (기존 j=0.7)
- **romaji nn+모음 파싱 수정**: `konnichiwa`가 `こんいちわ`로 파싱되던 버그 수정. `nn` 뒤에 모음이 올 때 첫 `n`만 ん으로 변환.

### Added
- **BeamDecoder 규칙 기반 폴백**: 학습 데이터에 없는 한글도 자모 분해 → 로마자 → 히라가나 규칙 기반 변환으로 처리
- **일본어 위키피디아 학습 데이터 통합**: 110K 문장 (191MB) 코퍼스 추가, `build_from_external_corpus()` API
- **종성 변환 테스트 추가**: `test_fallback_jongseong_n`, `test_fallback_jongseong_various`, `test_fallback_konnichiwa_full`

### Changed
- `phoneme.rs`: ㅉ(13) 매핑을 `[ch(0.4), j(0.3), z(0.2), ts(0.1)]`로 변경
- `phoneme.rs`: ㅘ(9) 매핑에 `a(0.3)` 대안 추가
- `phonetic_decoder.rs`: 종성 처리를 base syllable 변환 후 suffix 직접 부착 방식으로 변경

### Added
